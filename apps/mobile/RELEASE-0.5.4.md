# BeanMora mobile 0.5.4 (Android 14)

Coffee details restore **شخصية البن / Coffee personality** only when the roaster's tasting notes, acidity, sweetness and body are documented. The card uses compact tasting illustrations and attribute tiles, keeps published scores on their original scale, and shows qualitative descriptions without converting them into scores. Arabic attributes read from right to left. Partial records keep their available facts and source under **إيحاءات المحمصة / Roaster tasting notes**.

The **البن والإيحاءات / Coffee & taste** directory has a **شخصية البن مكتملة / Complete personality** filter. Re-entering the directory clears that filter, and Arabic flavor searches find translated notes. Roast appears once inside the sensory card. Recipe navigation and the compact xBloom layout introduced in 0.5.3 remain included.

Sixteen complete public profiles are now documented and applied to the existing catalog: three official five-block numeric profiles from THE BARN and thirteen qualitative profiles from nine other roasters. The source audit checked 194 existing official URLs and preserves exact product/lot identities. Public verification confirms 214 coffees, 33 profiles with source-backed attributes and 160 coffees with published notes. [Evidence and guarded repair](../../supabase/research/coffee-personality-2026-10-05/README.md) include the original values, translations, fetch hashes and verification. Oasis keeps its documented citrus/cocoa/body facts while its full card awaits documented acidity.

Validation: mobile TypeScript and unit/data checks passed; all 42 browser journeys were validated locally, including the new full/partial profile and directory-filter cases. The final Arabic order was checked at tablet width and rotation. Metro export succeeded for Android, iOS and web. The content repair passed a rollback-only dry run, exact-value checks, an idempotent replay and a public anonymous SDK read.

This change does not produce a signed APK or update an installed APK. Build the existing Expo project from GitHub `main`, base directory `apps/mobile`, Android profile `preview` and its `production` environment, with auto-submit off. The finished build must identify **0.5.4 (14)** and the merged release commit. Download that build's APK and install it; the account screen should show **0.5.4**. Native physical-device and installation checks remain to be performed on that APK.
