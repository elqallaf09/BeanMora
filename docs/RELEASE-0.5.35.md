# BeanMora 0.5.35 — multilingual UI, search and assistant fixes

The reported cold xBloom recipe request with coconut and honey remains a recipe search after shopping and when it mentions a machine. Espresso seller requests return equipment and seller links. Brewer and serving constraints apply before the server limit and are rechecked by the client. Honey processing never becomes a confirmed honey tasting note. Missing notes are stated explicitly; published source mL, grind, model, temperature and steps are preserved.

Mobile supports Arabic, English, Japanese, French, Italian, Spanish, Brazilian Portuguese and Simplified Chinese. Settings persist the selected language and update the current screen and existing assistant answer in place. Six static translation packs cover all 3,083 registered messages. The inventory excludes code identifiers. Coffee terminology, all 218 displayed flavors, long guides and legal/knowledge messages received a semantic review. Corrections include cold brew, espresso yield, roast/grind descriptions, scales, baskets and Japanese/Chinese navigation and empty states. Product/model/source names and member prose preserve their identity. Unknown free-form publisher or member content is not unrestricted machine-translated.

Shared search recognizes 446 reviewed concepts, including countries and flavors, across all eight languages. Exact accented words take precedence over unambiguous accent folding; Japanese dakuten and Chinese text survive normalization. All query terms remain required, unknown names stay literal and punctuation stays bound RPC data. Country filters distinguish homonyms such as Spanish granada (pomegranate/Grenada). Native country names work in signup search without changing the selected screen language. Full-width and Arabic digits work in measurement fields; French, Italian, Spanish and Brazilian Portuguese decimal commas preserve quantities without accepting mixed grouping separators. Member titles and steps are not normalized or rewritten.

Translation packs and reviewed dictionaries ship as static data. Translation models and paid AI services are not runtime dependencies. The assistant remains a deterministic coffee-domain assistant. Local arithmetic, offline lessons, units and existing answer traces retain their original facts.
