# BeanMora application audit — 10 October 2026, Kuwait time

The review covers the Next.js application, Expo source and exports, live database/storage permissions, dependencies, navigation and controlled failure states. Source integration includes main `4bda09d` (mobile 0.5.25 and the subsequent 30-second rotation and soft-button changes). Browser fixtures are isolated from production; SQL fixtures use actual roles and roll back.

## Database rollout

Applied forward migrations, with filenames matching the connected project's history:

- `20261009210202_audit_direct_voice_owner_index.sql`
- `20261009212607_audit_bean_corrections.sql`
- `20261009233408_audit_catalog_watch_and_report_contracts.sql`

All 92 public tables have RLS enabled. All six public views use invoker security. The catalog repair adds `product_watches`, `catalog_change_events` and `product_alert_deliveries`; owner policies protect watches and deliveries, pending changes remain private, and only confirmed evidence can produce an alert. The delivery ledger prevents duplicates on reconfirmation. Internal trigger functions are not callable by ordinary API users.

The new actual-role suite checks member ownership, guest/anon denial, unreviewed-product privacy, forged report rejection, moderator updates, baseline versus changed price evidence, exactly-once alerts, stopping a watch and account-deletion cascades. Fixtures roll back. The original 17 SQL suites passed on the earlier audit baseline; relevant suites are rechecked after the catalog change.

No real user account, catalog row, message or media object was deleted. No historical alerts were backfilled.

## Remaining limits

1. **Auth settings:** leaked-password protection remains disabled. The connected organization is Pro and supports the feature, but the available connector has no supported Auth-config write operation and the local Supabase CLI is not authenticated. No paid-plan change was made.
2. **Database engine:** the live server is PostgreSQL 17.6. Review the provider's supported upgrade path, compatibility and maintenance window for its newer security release before upgrading. No engine upgrade was performed.
3. **Mobile dependency metadata:** raw npm audit still reports 15 high tooling findings and zero critical findings. Installed security backports, regression checks and runtime sourcemap exclusions are verified, with an empty exception list. Raw audit is not clean; replace backports with compatible patched upstream versions when available.
4. **Administrative approval:** approval is still a sequence of browser writes. Later failures can leave an intermediate draft; use an atomic idempotent RPC before treating the entire approval as failure-safe.
5. **Database hygiene/performance:** RLS initialization-plan, permissive-policy, unused-index, public-extension and Auth allocation notices remain. Public member-profile functions and guest-owned reads have intentional behavior; do not revoke access or remove indexes merely to clear an advisor.
6. **Content quality:** earlier source inventory found missing covers, localized titles and catalog logos. Existing fallbacks can still display usable content. Fill gaps from evidence rather than inventing data; normalized-field gaps do not necessarily mean source JSON or preparation steps are absent.
7. **Native/release evidence:** physical iPhone/Huawei camera, microphone, OS sharing, deep links, Google/email delivery, background lifecycle, signed builds and store-install paths have not been exercised here. No signed APK/IPA is produced by an Expo export. Git integration alone does not update an installed app.
8. **Typing scope:** generated database relations/RPC contracts now replace the database-wide `any`. Some existing rendering/helper casts remain; this is not a claim that every application cast has been removed.
