# BeanMora application audit — 9 October 2026 UTC

Baseline: `d4fc8b4acb766a8a2baed40d221da15e2ceb92e7` (main, mobile 0.5.23).
The review covers the Next.js application, Expo source and exports, live
database/storage permissions, dependencies, navigation and controlled failure
states. Browser fixtures are isolated from production. Database fixtures run
with actual roles and roll back.

## Confirmed problems and repairs

| Problem | Result | Validation |
| --- | --- | --- |
| An ordinary member could insert a data correction already marked accepted, with fabricated reviewer metadata. | Inserts must be owner-scoped, open and unreviewed. Existing moderator-only updates remain enforced. | Reproduced in a rolled-back transaction before the change; actual member/guest/anon/moderator tests pass afterward. |
| The coffee detail “Report incorrect info” link led to a missing route. | Added a bilingual correction page/form using the existing private correction workflow. The schema now accepts bean targets and bounds their text. Failures retain the form and allow retry. | Both languages exercised through the actual link, with failed and successful controlled submissions. |
| Discover’s custom filter trigger dropped Radix event/accessibility properties and its ref. Clicking it did nothing. | Forward the trigger properties and ref to the underlying button. | A regression test failed before the repair and passed afterward; dialog opening, Escape and focus return are checked. Browser tests cover apply/reset in both languages. |
| Discover counted the default newest ordering as an active filter, so the unfiltered page showed a badge of 1. | Exclude default ordering from the badge count. | Actual unfiltered, applied and reset states in the bilingual filter browser tests. |
| Unmatched URLs could return a 404 document without HTML/body tags because the passthrough top-level layout was not a valid document root. | Use the existing locale layout as the document root and a complete bilingual global 404. Return links lead to the public locale landing pages. | Production build, all page routes, raw 404 document checks and actual recovery-link navigation. |
| Opening a mobile coffee personality source could reject without feedback. | Revalidate the URL, catch the rejection, show a localized error and clear it on retry. | Arabic/English browser regressions; iOS/Android/web exports. The existing parser already validated source URLs: this is not evidence of a discovered executable-URL exploit. |
| The selected mobile “For you” action had an empty callback. | It now calls the normal navigation action. | Source inventory and existing navigation coverage. |
| Voice verification owner lookups had an unindexed foreign key. | Added `private.direct_voice_checks(user_id)` index. | Index verified, missing-FK-index advisor cleared, account/social SQL regressions pass. |
| Onboarding looked up experience labels in a namespace that did not contain them, displaying translation keys in both languages. | Reuse the existing localized experience labels from the auth namespace. | The first GitHub run recorded missing-message errors in Arabic/English. Browser regression visits all four steps and checks every option label. |

## Security evidence

- All 89 public tables have RLS enabled. The five exposed views use invoker
  security. This is an inventory result, not proof that every possible policy
  composition is secure.
- Seventeen transactional SQL suites passed: access hardening, account
  deletion, media trust, brew outcomes, community, configured brewing/saves,
  deep search, equipment reviews, guest access, member social, contributions,
  public catalog, recipe scoring, roast lab, search maintenance, serving search
  and the new bean correction suite.
- Private recipe/post/member/profile-gallery/direct-audio/story buckets remain
  private. Public avatars and reviewed catalog images are intentional. Media
  ownership, private profiles, message participants, blocking, expiry and guest
  write restrictions are covered by SQL/browser scenarios.
- The deployed assistant v2, direct-audio verifier v2 and message cleanup v3
  were retrieved. All nine deployed source files exactly match repository
  files. Their application-side authorization checks were reviewed even though
  gateway `verify_jwt` is disabled. The ingestion source is present in the
  repository but is absent from the deployed function inventory.
- The direct-expiry cron is active every five minutes. Its latest four observed
  executions succeeded; five observed HTTP responses were 200 with no timeout.
  The observed expired-message count and audio-cleanup queue were both zero.
- No secret pattern matches were found in 671 scanned source files or 89 generated
  bundle/map files. Pattern scanning is not a complete secret-history audit.
- Web npm audit reports zero known vulnerabilities at all severities.
- Mobile raw npm audit still reports 15 high findings and zero critical
  findings. They arise from two affected tooling leaves (`braces` and
  `node-forge`) and propagated consumers. Installed source backports passed
  independent integrity/exploit verification and the audit gate; the exception
  list is empty. All 36 tooling/audit/runtime regression tests passed. The
  affected tooling is absent from all three exported runtime sourcemaps. Do not
  report the mobile raw audit as clean or remove these verification gates.

Automatic approval review rejected direct production function probes because
maintenance endpoints could modify data. No live mutation probe was executed.
Deployed source inspection and existing cron execution records were used
instead. This does not demonstrate every live POST authorization path.

  The committed full suite contains 137 scenarios. All 137 passed in the first
  GitHub mobile run on PR #50, together with online Expo compatibility,
  Expo Doctor 21/21 and all three runtime exports.
- Web unit tests, recommendation tests, brew outcome tests, security
  regressions, typechecks, lint and production builds passed locally. The new
  filter regression was also checked before and after its fix.
- Final local results: 220 web unit tests, 31 recommendation tests, 37 brew
  outcome tests and nine security regressions. The wide Chromium run passed
  38 scenarios, including all 53 routes in both languages; four subsequent

## Remaining work, ordered by impact

1. **Auth configuration:** leaked-password protection remains disabled in the
   live advisor snapshot. Enable it through supported Auth settings after
   checking plan availability; no paid-plan changes were made.
2. **Community web error feedback:** `PostLikeButton` changes local state before
   confirming the write and does not roll it back on a database error.
   `PostMoreMenu` ignores report-insert errors and clipboard failures. These
   source-level findings remain open; add explicit retry/failure behavior and
   behavioral tests before claiming every failure path is handled.
3. **Database type contracts:** `src/lib/supabase/types.ts` still aliases the
   database to `any`. Typecheck passes do not validate those query shapes.
   Generate real types and address inference differences in a focused change.
4. **Dependency maintenance:** replace the verified mobile tooling backports
   when compatible patched upstream packages become available. Keep raw audit
   findings visible until then.
5. **Database performance/hygiene:** seven RLS initialization-plan notices,
   167 permissive-policy occurrences, 85 observed unused indexes and fixed
   Auth connection allocation remain. Do not delete indexes or merge policies
   merely to clear a dashboard. `pg_trgm` and `unaccent` in public also remain
   security hygiene warnings and require a compatibility-tested move.
6. **Content quality:** 512 of 3,451 public recipes lack a cover image; only
   285 have a stored Arabic title. Thirteen of 234 reviewed/published beans and
   20 of 127 reviewed equipment items lack a primary image. All 75 observed
   roasters lack a stored logo. Existing fallbacks may still display usable
   content. Source completeness flags need review rather than invented data:
   all 3,312 xBloom recipes retain dose/ratio/water in source JSON, and all
   3,451 recipes have steps despite many nullable normalized fields.
7. **Release/device evidence:** physical iPhone/Huawei/Android camera, microphone,
   recording/playback, OS sharing, deep links, Google/email delivery, background
   lifecycle, signed builds and store-install paths were not exercised here.
   Local WebKit execution was blocked by missing OS dependencies; the existing
   GitHub workflow uses a browser container to supply that coverage.
